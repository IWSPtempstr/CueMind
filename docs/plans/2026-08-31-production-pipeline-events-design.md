# 生产链路原生事件埋点设计

**状态：已确认。**

## 目标

为每个音频/卡片请求建立共享 `runId`，记录真实的 `capture`、`ASR`、关键词和前端渲染边界，供逐请求时间线测评使用。埋点必须旁路、脱敏且不能阻塞实时链路。

## 事件契约

事件名称为 `capture_start/end`、`asr_start/end`、`keyword_start/end`、`render_start/end`，以及已有请求阶段事件。每条事件包含 `runId`、单调时钟 `atMs`、事件名和可选的安全元数据。一个 run 内事件按追加顺序校验；倒序、重复边界或未知事件拒绝。缺失阶段保持 `null`，不得用推导值伪装真实事件。

## 数据流

桌面/麦克风录音段创建时生成或继承 `runId`；音频上传/本地转写在请求前后发出 capture/ASR 事件；context-card 路由在关键词模型调用前后发出 keyword 事件，并把 `runId` 放入响应 trace；卡片状态提交前后在浏览器记录 render 事件。事件通过 JSONL 旁路记录器落到本地报告目录，写入失败只记本地诊断，不影响主链路。

## 安全与边界

事件元数据只允许 ID、来源、状态和耗时，不写原始音频、完整转写、密钥或完整模型 payload。`render_end` 表示 React DOM commit 后的 `useLayoutEffect` 近似时间，不宣称操作系统合成器绘制完成。

## 验收

- 同一请求的所有原生事件共享 `runId`，时间戳单调；
- 事件序列非法时测试失败并拒绝写入；
- 旧数据可继续由评测器读取，推导事件显式标记 `derived`；
- 逐请求报告列出八个原生事件的阶段耗时和缺失计数；
- TypeScript、lint、build 及既有性能测试通过。
